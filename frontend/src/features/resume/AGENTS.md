# AGENTS.md · frontend/src/features/resume

> 本目录的规则。**就近优先**：与根 [`AGENTS.md`](../../../../AGENTS.md) 冲突时以本文件为准。

## 负责什么

**「接着做」入口**：列出能恢复的工作，点一条回到那个现场。

★★ 这一块是探索发现的**功能级缺口**补的：检查点、恢复逻辑、
`GET /v1/system/resume` 后端早就做完了，而界面上没有任何入口。

## 不负责什么

| 不在这里 | 去哪 | 为什么 |
|---|---|---|
| 恢复本身（切 worktree、脏检查） | `backend/internal/app/checkpoint` | 界面只负责让他看见、让他点 |
| 打开一个工作 | `features/chat` 的 `open` 意图 | 与左栏点已有工作**同一条路** |

## 依赖方向

| | |
|---|---|
| 允许 import | `@/api/library` · `@/models/resume` · `react-i18next` |
| 禁止 import | 其它 `features/*`（横向依赖） |

## 本域特有的坑

- ★★ **不自动恢复。** 接着做是用户的决定——自动跳进去的话，
  他打开应用想开个新工作，却发现自己落在昨天那个半截的现场里。
- ★★ **显示停在哪个单元**，不只是工作 id。只有 id 的话他看到的是
  「work-03 · work-05」两行，那两个词对他没有任何意义；
  他记得的是「我在做那个取消功能」。
- ★ **一个都没有时整块不显示**：那是绝大多数人每次打开应用的状态。
- ★ **查不了就安静地不显示**，不摆一条红字：他多半根本没有可恢复的工作，
  为一次后台查询失败在首屏摆错误提示，会让他以为应用坏了。
- ★ 排在主区**最上面**：往下滚才发现的话，他多半已经开了个新工作。
