## 这个目录干什么

**AI 想动你的东西，先问一句。** 权限卡片 + 待裁决队列。

这是整个产品里后果最严重的一处交互：点错一次，AI 就改了不该改的文件。

---

## 本目录的铁律

### 1. 按钮照 Agent 给的 `options` 渲染 ★

**不许自己造一套「允许 / 拒绝」。**

Agent 可能给三个、四个选项（「这个目录以后都允许」之类）。自己造的话，
多出来的那个就消失了，而用户根本不知道自己少了一个选择。

按钮的**文字**用 `option.name`（Agent 给的），只有颜色由我们按 `kind` 决定。

### 2. `optionId` 原样回传 ★★

它是 Agent 定义的**不透明字符串**。点哪个就回哪个，
**不许按 `kind` 重新匹配、不许排序后取第一个**。

搞错的话，用户点「拒绝」而 Agent 收到「允许」。

### 3. 点了才消失，不点它不会自己消失

| | 为什么 |
|---|---|
| 点了要立刻消失（R2） | 不消失的话用户不确定点上没有，很可能再点一次，而第二条应答会被 Agent 当成不认识的请求 |
| 不点不许自动消失（R3） | 用户去倒杯水回来，卡片没了、AI 也停着——他不知道刚才发生过什么，更不知道该做什么 |
| 提交失败要留下 | 静默移除的话，用户以为处理完了，而 AI 那边还在等 |

**没有超时、没有自动关闭。** 用户可能去泡了杯咖啡。

### 4. 不是弹窗

本单元的 `forbidden_changes` 明写「用弹窗打断非阻塞信息」是禁止的。

卡片长在时间线里，跟其余进展排在一起——用户能看到「它为什么要动这个文件」
的上下文，而弹窗会把上下文盖住。

### 5. 「写入边界外」没依据就别说

那是一句很重的话。乱说的话用户会对所有提示脱敏，真正越界那次他也不会看。

## 文案

全部走 i18n，**显式映射**不许模板拼接（`check-i18n` 会拦）。
工具类别各说各的话：读文件说「请求读取」，执行命令说「请求执行」——
全都说「请求权限」的话，用户没法一眼分出「它要看一下」和「它要跑一条命令」。

认不出的类别用兜底文案，**不把 `switch_mode` 这种原始码显示给用户**。

## 测试怎么写

按用户看得见的东西查询（`getByRole` / `getByText`），不查 class、不用
`data-testid` 兜底。写或改测试前先调 `web-ui-test` skill。

每加一条断言，问一遍「把实现改坏，它会不会红」——**造负例，别猜**。
