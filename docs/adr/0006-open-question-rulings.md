## 裁定原则

按这个顺序找答案，找到就停：

1. **协议/规范是硬约束** —— ACP 规范说 MUST 的，没有裁量空间
2. **设计稿是产品意图** —— 但它是稿，有笔误与自相矛盾，可以裁定哪个是笔误
3. **既有文档的推导** —— 从设计系统令牌、领域不变量能唯一推出的，不算发明
4. **工程默认值** —— 上面都没有时，选**可逆的、保守的、有明确代价论证的**那个
5. 以上都不适用 → **不裁定**，升级给人（见文末）

## P0 · 挡住 M0

### ⚑ Q1 · `initializing` / `initializing_failed` 入状态机，九态改十一态

**裁定：加入，共 11 态。初始状态从 `clarifying` 改为 `initializing`。**

设计稿两处冲突：§09 术语表列了 9 个状态词，但「新建工作」对话框写着
「创建失败时工作进入 `initializing_failed`，不会退回原目录执行」。

裁定「9 个是子集」而不是「initializing_failed 是笔误」，理由是后者说不通：
它描述的是一个**有明确后果的状态**（不退回原目录），必须有实体承载。
一个查得到、显示得出来、有转移规则的东西就是状态。

§09 那 9 个是**对话状态行显示的状态词**——`initializing` 阶段还没有对话，
自然不在那张表里。

```
initializing ─成功─→ clarifying
             └失败─→ initializing_failed   （终态）
```

`initializing_failed` 是终态：worktree 没切成，没有可执行的现场。
用户只能删掉重建，不能"恢复"。

**影响**：`AGENTS.md` §8 术语表、`constant.WorkState`、穷举测试、`openapi.yaml`。

### ⚑ Q3 · 一个 Work 只能有一个状态；`executing · 3/7` 里的 `3/7` 是进度不是状态

**裁定：状态机单状态。D2 触发时状态离开 `executing`，进入 `waiting_user`。**

设计稿看似矛盾（左栏显示 `executing · 3/7`，同一 Work 的抽屉说「已进入 `waiting_user`」），
但这不是矛盾——**是把两个正交的东西并排显示了**：

| 显示 | 是什么 |
|---|---|
| `executing` / `waiting_user` | **状态**，同一时刻只有一个 |
| `3/7` | **进度**：已验收单元数 / 总单元数，与状态正交 |

左栏列表项的格式是 `<状态> · <进度>`。D2 触发后应显示 `waiting_user · 3/7`——
设计稿那处画的是 D2 触发**之前**的时刻。

顺带解决「D2 是否阻塞 `executing`」：**阻塞**，状态离开 `executing`。
不阻塞的话「等待你决策」这个计数就没有依据。

`set_mode` 只在 Runtime 不提供 `configOptions` 时降级使用。**

## P1 · M1

### Q33 · 「发现新版本」**不**成为第 14 类事件

**裁定：不加。用 `GET /v1/system/update/check` + 设置页角标。**

事件流是 **per-Work** 的（`GET /v1/works/{id}/events`），而应用更新是**全局**的。
把全局事件塞进 Work 作用域的流里，会逼出「哪个 Work 该收到它」这种没有答案的问题。

13 类事件的封闭性有实际价值（前端过滤器由它生成、注册表穷举由它保证），
为一个不属于该作用域的东西破坏它不划算。

---

### Q34 · 简化版 `prepare` 遇到进行中的工作返回 `blocked`

**裁定：确认 M1 分章的失败安全方案。**

`prepare` 的契约是「保证更新不丢工作」。简化版还没有落检查点的能力，
那就**不能声称保证**——返回 `blocked` 并说明「暂不支持在有进行中工作时更新」是诚实的。

放行则等于撒谎：用户以为工作被保护了，实际重启后就没了。

---

### Q35 · Checkpoint 的最小版本挪进 M1

**裁定：M1 新增 `U1.7.3 · Checkpoint 最小实现`，M2 的 2.8 改为「完整 Checkpoint（含证据关联）」。**

> **编号变更（2026-08-07，里程碑按产品视角重建）**：原 `U1.7.3` 这个编号已废弃。
> 裁定的实质不变，落点改为——M1 先做更保守的「有工作在跑就拦住不更新」，
> 检查点与恢复整体在 `milestones/M4-trust.md` 的 `U4.1.2`。
> 本节以下内容保留原文，不修改。

`prepare` 的完整语义依赖 checkpoint，而 checkpoint 排在 M2——M1 内部无法闭环。
最小版只需要：记录 commit hash + Work 状态快照 + 事件游标。证据关联留给 M2。

### Q36 · 品牌判断禁令排除生成物

**裁定：`grep -rn 'codex\|claude'` 的检查范围排除 `internal/api/gen/`。**

## P2 · M2 领域

### Q7 · `acceptance_criteria` 是 `UnitContract` 的字段

**裁定：是。**

设计稿的契约 YAML 里没列它、抽屉里单独渲染，是因为它要和证据关联展示。
但**冻结契约却不冻结验收标准，等于没冻结**——实现方可以事后放宽标准让自己通过。

放进契约，抽屉的独立渲染只是 UI 呈现方式。

---

### ⚑ Q8 · `contract_revision` 期间 Work 处于 `planning`

**裁定：复用 `planning`，不新增状态。**

`contract_revision` 意味着要出新契约版本——那本身就是规划活动。

不加状态的理由：状态每多一个，穷举测试的组合、前端筛选器、迁移表都要跟着长。
`planning` 的语义（"正在产出或修订计划产物"）已经覆盖它，为一个子情形加状态不划算。

需要区分时看 `Decision.kind == contract_revision`，那是决策记录的职责。

---

### Q9 · `UnitContract` 由单元设计师产出

**裁定：单元设计师。计划架构师那栏是笔误。**

三个证据指向单元设计师：契约抽屉明写「由单元设计师产出」；
`unit_contract` 是单元设计师的 AI 操作；角色职责表里单元设计师写着
「把交接写成契约而不是 Prompt」。

计划架构师的产出是 `PlanVersion` + `Subplan DAG`。

---

### Q10 · Unit / Subplan 的状态集

**裁定：**

```
Subplan:  pending → executing → accepted
                             ↘ blocked（依赖未满足）
                             ↘ obsolete（重规划废弃）

Unit:     pending → contract_frozen → executing → reviewing
                                                ↘ accepted
                                                ↘ failed
                                                ↘ obsolete
```

取值全部来自设计稿实际出现过的词：`accepted · 3/3`、`executing · 0/2`、
`blocked · 0/2`、`契约未冻结`、`已废弃`。没有发明。

`obsolete` 而不是 `deprecated`：后者在 Skill 上已占用，语义也不同
（Skill 的 deprecated 是"不推荐但可用"，Unit 的 obsolete 是"重规划后作废"）。

---

### Q11 · `superseded` 同时用作 Attempt 与 Evidence 状态，保持不变

**裁定：不改。**

语义确实相同——「被后来的取代」。Go 的具名类型（`AttemptStatus` / `EvidenceStatus`）
天然隔离，不会串。为了避免"同名"而造两个词反而增加认知负担。

---

### Q12 · Attempt 增加 `completed` 状态

**裁定：加。**

```
running → completed → accepted / rejected / superseded
```

`completed` = 执行结束、报告已产出、**等待审查**。

不加的话，Work 处于 `reviewing_unit` 时 Attempt 无状态可表达——
只能是 `running`（不对，它已经跑完了）或提前落 `accepted`（更不对，还没审）。

---

### ⚑ Q13 · Runtime 是注册表，不是二值枚举

**裁定：注册表。`openapi.yaml` 的 `RuntimeName` 从 `enum: [claude, codex]` 改为 `string`。**

两个理由：设计稿设置页已经出现第三项 `acp-sidecar`；
`design-principles.md` §2.5 明确要求「加第 3 个 runtime 只加一个包 + 登记一行」，
enum 会逼着改契约。

代价是丢了 schema 层的取值校验——用 `pattern` + 服务端查注册表兜住。

## P2 · 设计缺口

> 以下全部**从既有令牌与设计规则推导**，不是发明。

### ⚑ Q14 · 设置页 tab 与 §08「选中态」不矛盾——它们是两类控件

**裁定：tab 用 `--color-surface` 底 + `--color-text` 字是对的，不改。**

§08 的「选中 = accent-900 底 + accent-300 字」管的是**选择控件**
（列表项、下拉项、筛选胶囊）——它们表达"我选了这个值"。

tab 是**导航**，表达"我在这一页"。导航的当前项不该用强调色抢注意力，
否则页面上会同时有两处 accent 竞争（tab + 页内的真正选中项）。

设计规范补一条区分说明，不改现有取值。

### Q15 · 输入框：沿用设计系统 `.input`，只调到密集档

`.input` 已有完整定义（surface 底、divider 描边、accent caret、focus 描边转 accent）。
Duet 层只需把尺寸从 `min-height:36px / 14px` 调到密集档 `24–26px / 11.5–12px`，
与按钮对齐。placeholder 用 `--color-neutral-600`，校验错误用 `--color-fail` 描边。

**这是推导不是发明**：密集档的数值来自 §03，颜色来自既有语义色。

### Q16 · 表格：沿用 `.table`，只调密集档

`.table` 已有行级渐变分隔线、`th` 10px uppercase。Duet 层调整：
单元格 `padding` 用 `--space-2`、字号 12.5（§02 已规定「表格单元 12.5」）。

### Q17 · 空状态 / 骨架屏 / 错误态 / SSE 断线

| 状态 | 规格 |
|---|---|
| 空状态 | 居中单行，`--color-neutral-600`，12.5px。**不画插图**（与"工程化、精准"的语气一致） |
| 骨架屏 | **不做**。用「加载中：1.5px accent-400 圆环」（§08 已规定），骨架屏是另一种视觉语言 |
| 错误态 | inset 卡 + `--color-fail` 文字色 + 重试按钮（次操作档） |
| SSE 断线 | 窗口栏右侧一枚 `--color-fail` 小圆点 + tooltip「事件流已断开，正在重连」 |

### Q18 · 「禁止自绘 SVG」管的是图标，不管数据图表

**裁定：明确区分，补一条规范说明。**

§04 的禁令原文是「禁止 emoji、自绘 SVG **图标**」——上下文是图标来源。
数据图表（折线、环形）用内联 SVG 是唯一合理方式，不在禁令范围。

图表配色：`--color-accent-600` 单色主序列 + `--color-neutral-800` 网格线。
**不引入第三种语义色**——多序列用透明度分层，不用新颜色。

### Q19 · toast：z-index 40

在 `--z-drawer: 26` 与 `--z-tooltip: 60` 之间取 `--z-toast: 40`。
raised 底 + `--shadow-lg`，右下角，3 秒自动消失，可手动关。

### Q20 · 动效：120ms / 180ms，`prefers-reduced-motion` 全禁

| 场景 | 时长 | 缓动 |
|---|---|---|
| hover / 焦点 | 120ms | `ease-out` |
| 抽屉滑入 | 180ms | `cubic-bezier(.2,0,0,1)` |
| 浮层淡入 | 120ms | `ease-out` |
| 加载圆环 | 800ms 循环 | `linear` |

`@media (prefers-reduced-motion: reduce)` 下**全部置 0**，包括加载圆环
（改为静态描边 + 文字）。

推导依据：这个系统的基调是克制（"强调色只做线与光"、"加载中不用旋转图标"），
动效也该短促、不炫技。

### Q21 · 搜索 / 命令面板暂时移除

**裁定：窗口栏的 `搜索 ⌘K` 按钮从 M0–M4 范围内移除，列入 M4 之后。**

它不是"缺口"是"新功能"——设计稿只有一个入口按钮，没有面板设计。
做半成品不如不做。移除按钮是可逆的、保守的。

### Q22 · 敏感值掩码：前缀明文 + 定长圆点，不可展开

设计稿显示 `ghp_FaJhrnU0aCTGrF9H••••••••••••`：前 20 字符明文 + 12 个 `•`。
规格化为：**前 20 字符 + 固定 12 个 `•`**（不反映真实长度——反映长度会泄漏信息）。

**不提供展开**。需要核对时用「验证」按钮（设计稿已有），由后端去验。
提供「复制」按钮，复制的是完整令牌。

### Q23 · 补三个圆角令牌，accent-500/200 进用法表

```css
--radius-xs: 2px;    /* 进度条填充 */
--radius-2xs: 3px;   /* 角标 */
```

`--color-accent-500`：进度条填充的 hover 态；
`--color-accent-200`：极少用，仅用于 accent-900 底上需要更高对比的文字。

### Q24 · 面包屑

`11.5px`，分隔符 `/` 用 `--color-neutral-700`，中间段 `--color-neutral-500`，
末段 `--color-neutral-300`。中间段可点击（hover 转 accent-300），末段不可点。

## P3

### Q25 · 「全部」= active + 已失效；候选单独计

设计稿的 `全部 12 · active 9 · 候选 2 · 已失效 3` 里 9+2+3=14≠12。
**裁定：`全部` 不含候选**（9+3=12 ✓）。

理由自洽：候选**还不是记忆**，它在等审核。把它计入「全部记忆」会让
「这个项目有多少记忆」这个数字失去意义。

### Q26 · 取值域

```
confidence   ∈ { low, medium, high }
sensitivity  ∈ { public, internal, secret }
```

`internal` 来自设计稿实际显示值。三档足够——五档以上人分不清。

### Q27 · 候选晋升不改写 ID

**裁定：`cand-07` 晋升为 active 后保留原 ID，只改 `status`。**

改写会断掉 `source_refs`，且历史事件流里的引用会失效。
ID 的作用是"指向同一个东西"，晋升没有改变它是哪个东西。

> 顺带澄清：设计稿里 `cand-07` 与 `mem-203` 是**两条不同记录**，
> 不是同一条的前后状态。

### ⚑ Q28 · 项目 Skill 覆盖全局同名，不报错

**裁定：项目优先 + 在注入清单里显式标注「覆盖了全局同名 skill」。**

这条**推翻**了 `domain-model.md` 的 INV-SKL-10（要求返回明确错误）。

理由：报错会让用户卡住且**无法自解**——他既不能改全局 skill（那是别人的项目共用的），
也不好改项目 skill 的名字（那是项目的约定）。而"项目覆盖全局"是所有配置系统的
默认直觉，符合预期。

代价是可能静默用错——用显式标注补上，不用报错。

### Q29 · L3 去标识化：三条规则，不做正则脱敏

1. 去掉项目名与仓库路径
2. 文件路径去掉项目前缀，保留相对路径
3. **人工审核**（本来就是必须的）

**不做正则脱敏**——正则脱敏在自然语言上不可靠，且会给人"已经安全了"的错觉。
人工审核是唯一的防线，前两条只是减少审核负担。

### ⚑ Q30 · 合并到 `~/.acpflows/worktrees`

**裁定：不要 `~/.duet/` 这个第二个顶层目录。**

设计稿的 `~/.duet/worktrees` 与 `~/.acpflows` 并存没有理由，是早期遗留。
两个顶层目录意味着：卸载要清两处、备份要备两处、隔离守卫要护两处。

**影响**：`platform.Paths.WorktreeRoot()`、隔离守卫的受保护列表、设计稿设置页文案。

### Q31 · 并发上限默认 3，可配置

每个 Work 一个 ACP 子进程（node，实测约 200MB），加上 SQLite 单写者，
3 个是保守起点。有性能数据再调。

超限时**拒绝新建并说明原因**，不排队——排队会让用户以为卡死了。

### Q32 · 角色卡显示「本次实际使用」，不是配置

设计稿显示 `claude · sonnet · 中`，同时设置页写「模型与推理强度不在协议里，这里不设」。
两者可以共存：**显示的是观测结果，不是配置项**。

数据来自 `set_config_option` 回读的 `currentValue`，记在 `Attempt` 上（不在 `Role` 上）。
角色卡上标注为「本次使用」，且**不提供修改入口**。

## 里程碑划分

### Q37 · 报表指标口径

| 指标 | 定义 |
|---|---|
| 一次通过率 | 首次 attempt 即 `accepted` 的 Unit 数 ÷ 已验收 Unit 总数。**`obsolete` 不计入分母** |
| 平均单元耗时 | 已验收 Unit 的「最后一次 attempt 结束 − 第一次 attempt 开始」均值，**扣除 `waiting_user` 时长** |
| 驳回原因分布 | 按 review 的四类结论计数 |
| Runtime 使用 | 按 `OperationInvocation` 次数，**不含重试**（设计稿已规定） |

「扣除 `waiting_user` 时长」是关键：一个过夜的 D2 会把均值污染到毫无意义。

### Q38 · 三个隔离开关默认全开（最严）

| 开关 | 默认 | 理由 |
|---|---|---|
| 关闭 Runtime 机器级记忆 | **开** | 多会话串味是数据串扰，不是体验问题 |
| 禁用未授权项目 MCP Server | **开** | MCP 是任意进程执行；用户会用 Duet 打开来路不明的仓库 |
| 允许 Runtime 内建 Skill | **开** | 它去不掉（见 field-notes §4），开关只是**如实告知**而非真能关 |

第三个开关要在 UI 上标注「内建 Skill 无法关闭，此开关仅用于知情」——
提供一个关不掉的开关比不提供更糟。

### Q39 · Work 工作记忆 = `scope=work` 的 Memory

不新增第三种存储。md + DB 索引那套机制完全够用，加一种存储要付对账、迁移、
备份三份成本，换不到任何东西。

### Q40 · 启动恢复挪到 M1

`U4.7.1` → `U1.8.4`。它依赖 M1 自己的 `/system/resume` 与 Checkpoint 最小版（Q35），
放 M4 会让它在整个里程碑里一直是孤立的并行链。

> **编号变更（2026-08-07）**：原 `U4.7.1` / `U1.8.4` 两个编号均已废弃，
> 落点见 `milestones/M4-trust.md` 的 `U4.1.2`。裁定实质（更新不能丢工作）不变。

### Q41 · 三个隔离开关全划进 M3（含设置页 UI）

避免 M3/M4 之间唯一的跨里程碑依赖。开关的实现与 UI 在一起做，改同一批文件。

### Q42 · M2 的 13 类事件渲染器**全做**

注册表的类型签名是 `{ [T in EventType]: EventRenderer<T> }` —— 穷举，
缺一类 `tsc` 就红。做 13 个（其中几个是"暂不支持"的占位）比做 5 个
然后破坏穷举好得多：穷举一旦破坏，新增第 14 类时就没有编译期保护了。
