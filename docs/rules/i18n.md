# 国际化（i18n）

> 现阶段支持两种语言：**简体中文 `zh-CN`（默认）** 与 **英文 `en-US`**。
> 设计稿里已有对应设置项：设置 → 通用 → 界面语言。
>
> 核心规则一句话：**组件里不许出现用户可见的字面量文本，一律走 `t('key')`。**

---

## 1. 技术选型

| 项 | 选择 | 理由 |
|---|---|---|
| 库 | `i18next` + `react-i18next` | 生态最大，类型安全 key，AI 参考实现多 |
| 词条文件 | `frontend/src/i18n/locales/<locale>.json` | JSON 便于脚本校验与外部工具处理 |
| 类型 | 由 `zh-CN.json` 生成 `resources.d.ts` | key 写错编译期就红 |
| 默认语言 | `zh-CN` | 设计稿的一手文案是中文 |
| 回退 | `zh-CN` | 英文缺词条时显示中文，**不显示 key** |
| 语言检测 | 读用户设置 → 系统语言 → 默认 | 用户设置优先 |

```
frontend/src/i18n/
├── index.ts              初始化与实例
├── locales/
│   ├── zh-CN.json      ★ 词条真源（新词条先加这里）
│   └── en-US.json
└── resources.d.ts        由 zh-CN.json 生成，不手改
```

## 2. 什么翻译，什么不翻译 ★

这条比"怎么翻译"更重要。**翻错对象比不翻译更糟。**

### 必须翻译

- 所有界面文案：标题、按钮、说明、占位符、空状态、错误提示、tooltip
- 日期时间、数字、复数形式（用 `Intl`，不要手拼）

### 绝不翻译

来自根 [`AGENTS.md`](../../AGENTS.md) §8 术语表，**中英两版界面里都保持英文原值并等宽显示**：

| 类别 | 例 |
|---|---|
| 状态词 | `clarifying` `planning` `ready` `executing` `reviewing_unit` `waiting_user` `paused` `completed` `failed` |
| 审查结论 | `accepted` `implementation_fix` `contract_revision` `global_replan` |
| 决策等级 | `D0` `D1` `D2` `D3` |
| ACP 方法名 | `session/new` `session/set_mode` `session/request_permission` `session/cancel` |
| 记忆/Skill 状态 | `active` `candidate` `deprecated` `draft` |
| 标识符 | `unit-012` `mem-203` `ck-07` `plan v5` |
| 路径、分支、命令、commit hash | `~/.acpflows` `duet/work-08` `cargo test` `abc123` |
| 文件名、类型标签 | `acp-protocol.md` `constraint` `experience` `fact` |

> 理由：这些是**可被复制粘贴到终端或代码里的字符串**，翻译会让它们失效。
> 设计规范也要求它们等宽显示——等宽 + 英文原值是一体的。

### 术语的中英对照

需要翻译的产品术语，两版对照固定，不许临时另起译名：

| 中文 | English | 标识 |
|---|---|---|
| 工作 | Work | `Work` |
| 计划 | Plan | `PlanVersion` |
| 子计划 | Subplan | `Subplan` |
| 单元 | Unit | `Unit` |
| 单元契约 | Unit Contract | `UnitContract` |
| 尝试 | Attempt | `Attempt` |
| 证据 | Evidence | `Evidence` |
| 检查点 | Checkpoint | `Checkpoint` |
| 决策等级 | Decision Level | `D0`–`D3` |
| 记忆 | Memory | `Memory` |
| 角色 | Role | `Role` |
| 运行时 | Runtime | `Runtime` |
| 权限裁决 | Permission Ruling | `request_permission` |
| 会话模式 | Session Mode | `set_mode` |

## 3. 后端不返回用户可见文案 ★

这是 i18n 带来的**跨前后端硬约定**，必须在写第一个 API 之前定死。

```
✗ 后端返回：{ "detail": "契约已冻结，不能修改" }        ← 无法翻译
✓ 后端返回：{ "type": "contract_frozen", "params": { "unit_id": "unit-012" } }
   前端翻译：t('error.contract_frozen', { unitId })
```

### 规则

| | |
|---|---|
| 错误 `Problem.type` | 机器可读的稳定错误码（`snake_case`），**前端据此查词条** |
| `Problem.detail` | 只给开发者看的英文调试信息，**界面不直接展示** |
| `Problem.params` | 结构化参数，供词条插值 |
| 枚举值 | 原样返回英文标识（`executing`），前端决定显示成什么 |

**后端日志、`detail`、代码注释可以是中文；凡是会出现在界面上的，一律走错误码。**

每新增一个错误码 → 同时加进 `api/openapi.yaml` 的错误枚举 + 两个 locale 文件。
`make check-i18n` 会校验错误码与词条一一对应。

## 4. 词条 key 规范

```
<域>.<组件或场景>.<用途>
```

```json
{
  "common.action.cancel": "取消",
  "common.action.confirm": "确认并继续",
  "conversation.input.placeholder": "补充说明、纠正范围，或直接提问…",
  "conversation.queue.hint": "unit-012 执行中 · 已入队 {{count}} 条",
  "settings.update.available": "发现新版本 {{version}}",
  "error.contract_frozen": "单元 {{unitId}} 的契约已冻结，需新增版本才能修改"
}
```

### 规则

- **扁平 key，点分层级**，不用嵌套对象——扁平结构便于脚本校验与全文搜索
- 域取值固定：`common` `conversation` `plan` `memory` `skill` `report` `settings` `roles` `project` `error`
- **禁止**用中文原文当 key（`t('取消')`）——改文案就会全线断裂
- **禁止**动态拼 key（`t('status.' + s)`）——静态分析查不出未使用/缺失词条。
  需要映射时写成显式的 `Record<Status, TranslationKey>`
- 插值用具名变量 `{{version}}`，不用位置参数
- 复数用 i18next 的 `_one` / `_other` 后缀，**不要手拼中文量词**

## 5. 组件里怎么写

```tsx
import { useTranslation } from 'react-i18next'

export function UpdateCard({ version }: UpdateCardProps) {
  const { t } = useTranslation()
  return (
    <div>
      {/* ✓ 界面文案走 t() */}
      <h4>{t('settings.update.available', { version })}</h4>

      {/* ✓ 状态词原样等宽，不翻译 */}
      <code className={styles.state}>waiting_user</code>

      {/* ✓ 纯图标按钮的 tooltip 也要翻译 */}
      <button title={t('common.action.close')} data-tt={t('common.action.close')}>✕</button>

      {/* ✗ 禁止：硬编码用户可见文本 */}
      {/* <button>一键更新并重启</button> */}
    </div>
  )
}
```

### 日期、数字、时长

用 `Intl`，不要手拼：

```ts
new Intl.DateTimeFormat(locale, { dateStyle: 'short', timeStyle: 'medium' }).format(d)
new Intl.NumberFormat(locale).format(1204)
```

例外：**等宽显示的时长与计数**（`2:14`、`3/7`、`+64 −12`）是数据不是文案，不走 i18n。

## 6. 强制手段

```bash
make check-i18n
```

校验四件事：

| 检查 | 失败条件 |
|---|---|
| key 集合一致 | `zh-CN.json` 与 `en-US.json` 的 key 不完全相同 |
| 无未使用词条 | 词条在代码里搜不到 `t('<key>')` |
| 无缺失词条 | 代码里 `t('x.y')` 但两个文件都没有 |
| 错误码覆盖 | `api/openapi.yaml` 的错误码枚举有词条没覆盖到 |

ESLint 规则拦硬编码文本：

```js
// eslint.config.js
'no-restricted-syntax': [
  'error',
  {
    // JSX 里出现中日韩字符的字面量文本 → 报错
    selector: 'JSXText[value=/[\\u4e00-\\u9fa5]/]',
    message: '界面文案必须走 t()，见 docs/i18n.md',
  },
],
```

英文字面量无法机械区分（`ok` 可能是变量名也可能是文案），
所以英文文案靠 `make check-i18n` 的「无缺失词条」反查 + 审查兜底。

## 7. 加一条新文案的完整流程

1. 在 `zh-CN.json` 加 key 与中文文案
2. 在 `en-US.json` 加同一个 key 的英文文案（**不许留空，不许只加一边**）
3. 跑 `pnpm gen:i18n-types` 更新类型
4. 组件里用 `t('key')`
5. `make check-i18n` 绿

**两个语言文件永远同进同退。** 只加中文的 PR 会被 CI 拦下。

---

## 8. 禁止清单

- ✗ 组件里硬编码用户可见文本
- ✗ 翻译状态词、标识符、命令、路径、ID（见 §2）
- ✗ 用中文原文当 key
- ✗ 动态拼 key
- ✗ 后端返回中文文案给界面展示
- ✗ 只更新 `zh-CN.json` 不更新 `en-US.json`
- ✗ 手拼日期/数字/复数格式
- ✗ 英文版把术语另起译名（对照表见 §2）

---

## 9. 开放项

1. 要不要支持繁体中文 `zh-TW` —— 等有需求再说，key 结构已经支持
2. 词条外部化（交给翻译平台）—— 现在两种语言手工维护成本可接受
3. 英文版的等宽 ID 与中文版排版差异 —— 等英文版实际跑起来再调
