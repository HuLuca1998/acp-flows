| | 里程碑 | 用户拿到什么 | 验收点 | 状态 |

**顺序由用户价值决定，不由技术依赖决定。**
M0 排第一是因为它是用户**最早能亲眼看到**的东西——开发机上打开浏览器就能看，不用等打包。
M1 紧随其后：用户验收发现问题 → 我改 → 他得拿到新版本，
没有一键更新，这个循环每次都要卸载重装。

## 每个单元走六步

```
① 里程碑 → ② 拆分单元 → ③ 单元实现计划
        → ④ 单元测试（代码）→ ⑤ 操作测试（UI）→ ⑥ 通知用户测试
```

★ **第 ⑤ 步最容易被跳过**：单测全绿证明不了按钮点得动、文案看得懂。
详见 [`milestones/README.md`](milestones/README.md)。

## 怎么用这份文档

- **接到一个需求先问它属于哪个验收点。** 对不上任何一条 → 用 `create-issue` 记下来，别顺手做
- 里程碑内的编号（`U1.2.3`）可直接用作 issue 标签与分支 slug
- **一个单元六步走完就在里程碑里标 `✓` 并注明提交号**，让下一轮 AI 知道进度
- `✓` 的含义是**六步全走完**，不是「代码写完了」
