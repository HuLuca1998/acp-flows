## 六个里程碑

| | 里程碑 | 用户拿到什么 | 验收点 | 状态 |
|---|---|---|---|---|
| **M0** | [基础框架](milestones/M0-foundation.md) | 打开就能看到完整界面轮廓，未做的地方是骨架占位 | V0 系列 | ✓ 完成 |

| **M2** | [能提需求，看得见 AI 在干什么](milestones/M2-talk-and-observe.md) | 加项目、提需求、AI 边做边显示 | V4 V5 V6 | 待开始 |

| **M4** | [值得信任](milestones/M4-trust.md) | 关掉能恢复、看得到计划与证据、重要决定等我拍板 | V9–V12 | 待开始 |
| **M5** | [越用越顺手](milestones/M5-polish.md) | 记住项目规矩、看得到效率、英文界面 | V13–V15 | 待开始 |

**顺序由用户价值决定，不由技术依赖决定。**
M0 排第一是因为它是用户**最早能亲眼看到**的东西——开发机上打开浏览器就能看，不用等打包。
M1 紧随其后：用户验收发现问题 → 我改 → 他得拿到新版本，
没有一键更新，这个循环每次都要卸载重装。

## 每个单元走六步

```
① 里程碑 → ② 拆分单元 → ③ 单元实现计划
        → ④ 单元测试（代码）→ ⑤ 操作测试（UI）→ ⑥ 通知用户测试
```

★ **第 ⑤ 步最容易被跳过**：单测全绿证明不了按钮点得动、文案看得懂。
详见 [`milestones/README.md`](milestones/README.md)。

## 怎么用这份文档

- **接到一个需求先问它属于哪个验收点。** 对不上任何一条 → 用 `create-issue` 记下来，别顺手做
- 里程碑内的编号（`U1.2.3`）可直接用作 issue 标签与分支 slug
- **一个单元六步走完就在里程碑里标 `✓` 并注明提交号**，让下一轮 AI 知道进度
- `✓` 的含义是**六步全走完**，不是「代码写完了」
