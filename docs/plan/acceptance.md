# 验收清单 · 用户视角

> **这份文档是给使用者看的，不是给开发者看的。**
> 每一条都是**你能自己动手做、自己判断成没成**的一件事。
> 里面不出现任何代码、架构、技术名词。
>
> 技术怎么实现见 [`milestones/`](milestones/)——那是施工图，你不需要读。
> **两者的关系**：一个验收点通常要好几个技术单元才凑齐；
> 反过来，任何技术单元如果凑不进某个验收点，就该问它为什么要做。

---

## 怎么用这份文档

1. 我说「V3 可以验收了」，你就翻到 V3
2. 照着「你怎么试」那一列做一遍
3. 对照「应该看到什么」——**对不上就是没做完**，直接告诉我哪里不对
4. 「常见的做错的样子」是我自查用的：那些是看起来像做完了、其实没有的情况

**验收标准由你判断，不由测试判断。** 测试全绿但你用着不对，就是不对。

## 第零阶段：先让你看到它长什么样

> **这是你最早能亲眼看到的东西**，在开发机上就能看（不用等打包）。
> 功能还没做的地方用**骨架占位**——灰色条块 + 一句说明，
> 让你看得出「这里将来会有什么」，而不是白屏。

### 🚧 V0 · 我能打开它，看到完整的界面轮廓

| | |
|---|---|
| **你怎么试** | 我把服务起好，你打开 http://localhost:5173 |
| **应该看到什么** | 深色窗口、顶部是应用自己画的标题栏、左边一列导航。点导航的每一项，**七个页面都打得开**：对话 / 计划 / 记忆 / Skill / 报表 / 角色与 Runtime / 设置 |
| **做不到的样子** | 白屏；点了没反应；某一项点开是报错页 |
| **常见的做错的样子** | 未做的页面直接空白——**应该是骨架占位**，让你知道在做而不是坏了 |

### 🚧 V0.1 · 没做完的地方是骨架，不是假数据 ★

| | |
|---|---|
| **你怎么试** | 逐个点开还没做的页面 |
| **应该看到什么** | 灰色的占位条块 + 一句「这里将来是什么」 |
| **做不到的样子** | 页面上有看起来像真的数字（比如「一次通过率 87%」），但其实是编的 |
| **常见的做错的样子** | 为了「看起来完整」填假数据——**这比空白更糟**，你会在假信息上做判断 |

### 🚧 V0.2 · 我能切中英文

| | |
|---|---|
| **你怎么试** | 设置 → 通用 → 切换语言 |
| **应该看到什么** | 界面立刻变成英文，不用重启；切回中文也正常 |
| **做不到的样子** | 切了没变；中英混杂；切完要刷新才生效 |
| **常见的做错的样子** | 把状态词也翻译了——`executing` 这类词在中英两版里都应该保持英文原样 |

### 🚧 V0.3 · 我能看到版本号，并点得动「检查更新」

| | |
|---|---|
| **你怎么试** | 设置 → 应用更新 |
| **应该看到什么** | 当前版本号；进页面时自动查一次；结果是三种之一：有新版本 / 已是最新 / **检查失败** |
| **做不到的样子** | 看不到版本；点了没反应 |
| **常见的做错的样子** | ★ **断网时显示「已是最新版本」**——这是最坏的一种，你永远不会知道自己在用旧版 |

> V0.3 只是「看得到、点得动」。**真的能更新**是 V2，那需要先把应用打包发出去。

## 第一阶段：先让你能拿到它、并且能一直拿到新版本

> **为什么这两条排最前**：你验收发现问题 → 我改 → 你得拿到改完的版本。
> 如果没有一键更新，这个循环每次都要你卸载重装。
> 所以**第一个交到你手上的版本里就必须已经带着一键更新**。

### ⬜ V1 · 我能装上并打开它

| | |
|---|---|
| **你怎么试** | 我给你一个下载链接 → 下载 `.dmg` → 打开 → 把 Duet 拖进「应用程序」→ 双击打开 |
| **应该看到什么** | 一个深色的应用窗口打开了。窗口顶部是应用自己画的标题栏（不是 macOS 默认的那条）。左边能看到项目列表区域 |
| **做不到的样子** | 双击没反应；弹「无法打开，因为无法验证开发者」且没有解决办法；打开是白屏 |
| **常见的做错的样子** | 开发机上能跑，但换一台没装过开发工具的 mac 就打不开（漏打包了依赖） |

> 关于「无法验证开发者」：第一版会用简易签名，macOS 可能拦一下。
> 我会给你一条命令解除，**一次就好**。要彻底免掉需要苹果开发者账号（$99/年），
> 那件事等你说要不要再做。

### ⬜ V2 · 我能一键更新，不用重装 ★

| | |
|---|---|
| **你怎么试** | 我发一个新版本 → 你打开 Duet → 进「设置 → 应用更新」 |
| **应该看到什么** | 卡片上写着「发现新版本 X.Y.Z」「当前 A.B.C」，下面是这次改了什么。点「⟳ 一键更新并重启」→ 应用自己关掉再打开 → 版本号变成新的了 |
| **做不到的样子** | 一直显示「已是最新」（其实有新版）；点了没反应；更新完打不开了 |
| **常见的做错的样子** | ① 明明网络断了，界面却说「已是最新版本」——**这是最坏的一种**，你永远不会知道自己在用旧版<br>② 版本 1.10.0 出来了却提示不更新（比较版本号时把 10 当成比 9 小）<br>③ 更新时把你正在跑的工作弄丢了 |

> **「更新不丢工作」是这条的一半。** 如果更新时有工作在跑，
> 应该先停下来存好现场再更新，重启后能接着来。
> 现阶段先做保守版本：**有工作在跑就拦住不让更新**，并告诉你是哪几个。
> 等「暂停并保存现场」做好了，才改成自动处理。

### ⬜ V3 · 我能看出来它现在是什么版本、连没连上

| | |
|---|---|
| **你怎么试** | 打开「设置 → 环境检测」 |
| **应该看到什么** | 当前版本号；Claude 和 Codex 两个 AI 引擎各自「已安装 / 已登录」还是「未安装」；没装的话给出一键安装或者告诉你该敲什么命令 |
| **做不到的样子** | 页面空白；显示「未知」但不告诉你怎么办 |
| **常见的做错的样子** | 报错信息是给程序员看的（一串英文堆栈），没告诉你下一步该干什么 |

## 第二阶段：让它真的能干活

### ⬜ V4 · 我能把自己的代码项目加进来

| | |
|---|---|
| **你怎么试** | 左栏「项目 → 创建项目」→ 选一个你本地的代码文件夹 |
| **应该看到什么** | 项目出现在左栏列表里。点进去能看到这个项目下的工作列表（一开始是空的） |
| **做不到的样子** | 选了文件夹没反应；选了一个不是代码仓库的文件夹时不给提示 |
| **常见的做错的样子** | 直接在你的项目里乱写文件（应该只在它自己的隔离目录里放东西） |

### ⬜ V5 · 我能提一个需求，AI 会先跟我把需求问清楚

| | |
|---|---|
| **你怎么试** | 在项目里「新建对话」→ 输入一句话需求，比如「用户能取消正在运行的任务」 |
| **应该看到什么** | AI 开始追问缺失的细节（不是直接开写）。问完之后给出一份需求快照让你确认 |
| **做不到的样子** | 输入完没反应；AI 直接开始写代码不问 |
| **常见的做错的样子** | 界面卡住直到 AI 全部说完才一次性显示——**应该边说边显示**，像打字一样 |

### ⬜ V6 · 我能看见 AI 正在干什么

| | |
|---|---|
| **你怎么试** | 需求确认后让它继续做 |
| **应该看到什么** | 中间区域像一条时间线：AI 的消息、它在读哪个文件、在跑什么命令、思考摘要、每一步的结果。右上角能筛选只看某几类 |
| **做不到的样子** | 只有一个转圈圈，不知道它在干嘛；等好久才一次性刷出来一大堆 |
| **常见的做错的样子** | 显示的是「正在处理…」这种没信息量的字，而不是真的在做什么 |

### ⬜ V7 · AI 要动我的文件时会先问我 ★

| | |
|---|---|
| **你怎么试** | 让它做一个需要改文件的任务，特别是改到你没让它改的地方 |
| **应该看到什么** | 弹出一张卡片：「Codex 请求写入 ⟨某个文件⟩」，标明「写入边界外」，给你「允许一次 / 拒绝」两个按钮。**你不点它就一直等着** |
| **做不到的样子** | 没问就改了；问了但你点了没反应；卡片一闪而过 |
| **常见的做错的样子** | ① 悄悄改了你的文件才告诉你<br>② 你点「拒绝」它还是改了<br>③ 等你回答的时候整个界面都卡死了（应该只卡这一个任务，别的照常） |

### ⬜ V8 · 我能随时喊停 ★

| | |
|---|---|
| **你怎么试** | AI 正在执行时，点「取消」 |
| **应该看到什么** | 它停下来了，**并且已经做的部分还在**——改了哪些文件、跑了什么命令都能看到。连点两次取消不会出乱子 |
| **做不到的样子** | 点了不停；停了但现场全没了；界面卡住转圈 |
| **常见的做错的样子** | ① 界面显示「已取消」，但后台那个 AI 还在继续改你的文件、继续烧钱<br>② 取消之后再也看不到它之前做了什么 |

## 第三阶段：让它值得信任

### ⬜ V9 · 关掉再打开，工作还在

| | |
|---|---|
| **你怎么试** | 工作做到一半，直接关掉 Duet，再打开 |
| **应该看到什么** | 之前的对话、计划、进度都还在，能接着做 |
| **做不到的样子** | 一切从头开始；对话还在但 AI 不记得之前聊了什么 |
| **常见的做错的样子** | 界面上看着接上了，但 AI 其实是新会话、完全不记得前文——**看起来正常，实际全错** |

### ⬜ V10 · 我能看到它的计划，以及为什么改计划

| | |
|---|---|
| **你怎么试** | 点「查看计划」 |
| **应该看到什么** | 任务被拆成了几块，哪些做完了、哪些在做、哪些还没开始。改过计划的话能看到改了几版、每次为什么改 |
| **做不到的样子** | 只有一个进度条；计划被改了但看不出改了什么 |

### ⬜ V11 · 我能看到「凭什么说做完了」

| | |
|---|---|
| **你怎么试** | 一个任务做完后点「打开证据」 |
| **应该看到什么** | 改了哪些文件（能看 diff）、跑了哪些测试、结果是什么。每条验收标准对应哪个证据 |
| **做不到的样子** | 只写「已完成」；证据是 AI 自己说的一段话，不是真的运行结果 |
| **常见的做错的样子** | 「测试全绿」但点开发现根本没跑过测试 |

### ⬜ V12 · 重要决定会等我拍板

| | |
|---|---|
| **你怎么试** | 让它做一个需要改动较大的任务 |
| **应该看到什么** | 遇到重要岔路时停下来问你，给出几个选项和推荐，等你选 |
| **做不到的样子** | 自己做了主；或者什么屁大点事都问你 |

## 第四阶段：越用越顺手

### ⬜ V13 · 它会记住这个项目的规矩

| | |
|---|---|
| **你怎么试** | 用「记忆」页 |
| **应该看到什么** | 它从做过的事里总结出的经验条目。**新经验要你点了同意才会生效**，不会自己偷偷记 |
| **常见的做错的样子** | 自动把没验证过的东西记成「事实」，然后一直照着错的做 |

### ⬜ V14 · 我能看到它干得好不好

| | |
|---|---|
| **你怎么试** | 打开「报表」 |
| **应该看到什么** | 一次通过率、平均耗时、被驳回的原因分布、哪个 AI 用得多 |

### ⬜ V15 · 界面能用英文

| | |
|---|---|
| **你怎么试** | 设置里切换语言 |
| **应该看到什么** | 界面全部变成英文，没有中英混杂 |

## 给 AI 协作者：这份文档怎么用

### ★ 铁律：叫用户验收之前，自己先把这一列全走一遍

**「测试全绿」不等于「功能能用」。** 单元测试证明的是代码逻辑对，
证明不了界面点得动、文案看得懂、流程走得通。

叫用户之前必须做到：

1. **把应用真的跑起来**（`make dev`，或装好的 `.app`）
2. **用浏览器/应用界面照着「你怎么试」那一列真的操作一遍**，不是跑 curl，不是跑测试
3. **逐条对照「应该看到什么」**，包括文案是否与设计稿一致
4. **把「常见的做错的样子」逐条试一遍**——那些是看起来像做完了、其实没有的情况
5. 有一条对不上就**不要叫用户**，先修

报告时要给出你实际操作的证据（截图 / 页面文本 / 实际响应），
不是「我认为应该可以」。

> **把没自验过的东西交出去 = 把测试压力转嫁给用户。**
> 用户是来验收产品的，不是来当测试员的。

### 每个技术单元开工前，先回答一句话：它属于哪个验收点？
答不上来的，要么是地基（那就写清楚它是为了让哪个验收点成立），
要么就不该现在做。

验收点与技术单元的映射：

| 验收点 | 主要依赖 |
|---|---|
| V0 V0.1 | M0 的 S0.1（窗口与七页导航）· S0.4（骨架占位） |
| V0.2 | M0 的 S0.2（多语言） |
| V0.3 | M0 的 S0.3（设置页与更新区） |
| V1 | M1 的 S1.2（密钥 · 发版 · 干净机器可装） |
| V2 | M1 的 S1.1（更新界面与流程）+ M0 的 S0.3 |
| V3 | M1 的 S1.3（Runtime 检测） |
| V4 | M2 的 S2.1（项目与工作区） |
| V5 | M2 的 S2.2（会话生命周期）★ 依赖真的能起 Agent |
| V6 | M2 的 S2.3（事件流与时间线渲染） |
| V7 | M3 的 S3.1（权限请求与裁决） |
| V8 | M3 的 S3.2（两段式取消）★ 也是 V2「更新不丢工作」的前置 |
| V9 | M4 的 S4.1（会话恢复与检查点） |
| V10 | M4 的 S4.2（计划只增不改） |
| V11 | M4 的 S4.3（应用直接采集证据） |
| V12 | M4 的 S4.4（决策等级与阻塞） |

**改这份文档的规矩**：验收点只增不改。
已经交付的验收点如果发现描述不准，新增一条，不要改历史——
用户是照着旧描述验收过的。
