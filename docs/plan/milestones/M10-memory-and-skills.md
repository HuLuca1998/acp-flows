# M10 · 它越用越懂我的项目

> ★ 施工图在快做到时才建（`roadmap.md` 的规矩）。本文件 2026-08-10 建于 `M9` 完成之后。

## 目标

**干活时冒出来的经验，用户点一下就进了记忆库；下一轮它带着这些经验开工。**

★★ 这一步是 Duet 与「每次从零开始的 AI」的分界线。而它的底线是
**记忆由用户收下，不由 AI 自己写进去**——AI 自己写的话，
一条它误解的「经验」会一直影响后面每一轮，而用户从没同意过。

## 完成标志

用户自己做这五件事，全部成功：

1. 干活中冒出经验 → 消息里出现「**记忆候选**：… · 审核」
2. 点「审核」→ 决定收不收；收了进记忆库
3. 记忆页：按项目 / 跨项目分组，按 `active / 候选 / 已失效` 筛选，有类型
4. Skill 页：带**版本号**、**命中计数**、**校验态**（draft 说明为什么没过）
5. 下一轮对话的**注入行**里，能看到刚收的那条记忆

## 全局停止条件

1. 记忆**正文**要塞进数据库 —— 那违反 INV-MEM-8（正文只在 md 文件里，
   用户要能用任何编辑器改它）
2. AI 可以**自己**把记忆写成 active —— 那是这一步的底线
3. 命中计数要靠 AI 自报 —— 应用自己数（与 `M8` 的证据同理）

## S10.1 · 记忆正文

### ✓ U10.1.1 · 记忆正文的 md 读写

| | |
|---|---|
| `goal` | 记忆的正文在 md 文件里，读得出、改得动 |
| `allowed_changes` | `backend/internal/fsstore/memory/**` · `backend/internal/app/memory/**` |
| `forbidden_changes` | 正文进数据库（INV-MEM-8）；写用户项目目录之外的地方 |
| `stop_conditions` | 正文与索引的一致性要靠事务 —— 文件系统没有事务，先想清楚失败路径 |

**验收标准**

| # | 标准 | 断言 |
|---|---|---|
| R1 | 正文只在 md 文件里，DB 只存索引 | 断言 DB 里没有正文列 |
| R2 | 用户手工改过 md 之后，读出来是**新内容** | 改文件再读，断言变了 |
| R3 | md 文件不见了时**说清楚**，不当成空正文 | 断言报错且带路径 |
| R4 | 写正文**只写记忆库目录**，不碰用户项目 | 断言项目目录快照不变 |
| R5 | frontmatter 解析失败时保留原文 | 断言原文可读，只是结构化字段缺 |

**五条全做完。** R1 早就成立（`memory_repo_test.go` 的 `INVMEM8_TableHasNoContentColumn`
守着表里没有正文列），这里补的是另一半：正文的实际读写。

★ 写的时候删掉了一段 `filepath.Rel` 的「双保险」——它**永远进不去**
（能走到那行的 id 已经不含 `/` `\` `..`）。留着会让下一个人以为有两层
防御，而实际只有一层，他可能因此放心地把前一道放宽。

## S10.2 · 记忆候选

### ✓ U10.2.1 · 从对话里冒出记忆候选

| | |
|---|---|
| `goal` | AI 干活时发现的经验，变成一条待审核的候选 |
| `allowed_changes` | `backend/internal/app/work/**` · `backend/internal/app/memory/**` |
| `forbidden_changes` | AI 直接写 active（这一步的底线）；候选自动过期 |
| `stop_conditions` | 候选的去重要靠语义相似度 —— 先用「同一条正文」这个粗判据 |

**验收标准**

| # | 标准 | 断言 |
|---|---|---|
| R1 | 回复里的 `duet-memory` 围栏 → 一条 `candidate` | 断言状态是 candidate 不是 active |
| R2 | **AI 写不出 active**：状态由应用给 | 断言载荷里写 active 也被降成 candidate |
| R3 | 解析不出来时**不静默**，把原话给用户看 | 断言事件里带原因 |
| R4 | 同一条正文重复冒出来时**不重复建** | 断言第二次不新增 |
| R5 | 候选事件带着「审核」要用的 id | 断言载荷里有它 |

**五条全做完，且接到真实路径上**：每一轮的 `OnReply` 都套了
`withMemoryCapture`，角色提示词末尾都拼了 `memoryInstructions()`，
装配里 `SetMemories(db.Memories(), newMemoryBodies(...))`。

★★ R2 在**领域层天然成立**：解析出来的东西一律交给 `ProposeCandidate`，
它只造 candidate，压根没有别的入口。payload 里**故意没有 status 字段**——
留一个再去过滤的话，总有一天有人会「顺手支持一下」。

★★ 接线守卫断的是**真的传给 Agent 的 `AgentTurn.SystemPrompt`**，
不是某个函数的返回值。**验过负例**：拆掉 `role.go` 里那一行拼接，
它立刻红。提取器与「让它提」必须成对上线，否则解析那一整套是死代码。

## S10.3 · 注入与命中

### ✓ U10.3.1 · 注入清单与命中计数

| | |
|---|---|
| `goal` | 干活那一轮带着记忆与 Skill 开工，且每条记得被用过几次 |
| `allowed_changes` | `backend/internal/app/work/**` · `backend/internal/store/**` |
| `forbidden_changes` | 命中计数由 AI 自报；把没注入的算进清单 |
| `stop_conditions` | 注入的 token 预算超了要裁剪 —— 裁剪规则没定就停 |

**验收标准**

| # | 标准 | 断言 |
|---|---|---|
| R1 | 开场白里带着 active 记忆 | 断言 prompt 含那条记忆 |
| R2 | 注入清单**由应用记**，不问 AI | 断言清单来自我们拼的那份 |
| R3 | 命中计数每注入一次加一 | 断言两轮之后是 2 |
| R4 | 失效的记忆**不注入** | 断言 invalid / obsolete 不在清单里 |
| R5 | 一条都没有时不发空清单 | 断言没有「注入 0 条」这种噪音 |

**五条全做完，且接到真实路径上**：两处 `RunTurn` 的 `Prompt` 都过
`applyInjection`，装配里 `SetMemoryHits(db.Memories())`。R1 的判据落在
**真的发给 Agent 的 `AgentTurn.Prompt`** 上。

★★ R2 的判据是一条对抗性用例：AI 在回复里胡说「我参考了 mem-99」，
而清单里仍然只有真的发出去的那条。跟着它的说法走的话，
这份清单没有任何价值——用户正是靠它判断「它是不是带着我的规矩在干活」。

★ 顺带补上了 M7 完成标志第 3 条（干活时每条消息显示注入了什么）。
