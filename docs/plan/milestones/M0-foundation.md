# M0 · 基础框架：能打开，看得到完整轮廓

> 对应验收点 **V0**（[`../acceptance.md`](../acceptance.md)）。
>
> **进度（2026-08-07）**：六个单元全部走完六步流程，`make check` 与 e2e 全绿。
> 剩余的设计规范细节（对话时间线的 13 类事件形态、抽屉与对话框）随 M2 落地。
>
> **这是用户最早能亲眼看到的东西。** 在此之前所有工作对他都是不可见的。

## 目标

**打开应用就能看到完整的界面轮廓：窗口栏、左栏导航、每个页面都点得开，
能切中英文，设置页能看到版本并检查更新。**
还没做的功能用**骨架占位**——用户看得出「这里将来会有什么」，而不是白屏或 404。

## 完成标志

用户自己做这五件事，全部成功：

1. 打开应用 → 看到深色窗口、顶部自绘窗口栏、左栏导航
2. 点左栏每一项 → 五项导航都打得开，没有白屏（对话是默认主区，计划是悬浮面板）
3. 还没做的区域显示**骨架占位**（灰色条块 + 一句「即将上线」），不是空白也不是报错
4. 设置里切英文 → 界面变英文，切回来也正常
5. 设置 → 应用更新 → 看到当前版本，点「检查更新」有明确结果（有新版 / 已是最新 / 检查失败）

## 为什么骨架占位不是敷衍

**空白页让人以为坏了，骨架占位让人知道在做。**
它还有一个工程作用：把布局、导航、状态管理、多语言这些"横向的东西"
一次性打通并测住，后面每个功能页只需要往里填内容，
不必每次都重新处理"页面怎么进、标题怎么翻、加载中怎么显示"。

## 全局停止条件

触发任一条 **立刻停下来上报**：

1. 设计稿里找不到某个控件的样式条目——**先补设计条目再实现**（铁律 3）
2. 需要硬编码颜色、尺寸或用户可见文案
3. 需要在 `platform/` 之外 import Tauri
4. 骨架占位被做成"假数据"——占位就是占位，**不许编造看起来像真的内容**
5. 撞上 [`../open-questions.md`](../open-questions.md) 未决项

| `forbidden_changes` | 轮询检查（**进设置页时检查**，见 `adr/0007` 修订 3）；自动下载或自动安装 |

**验收标准**

| # | 标准 | 断言 |

| R3 | 已是最新时**不显示更新按钮** | 断言查不到该按钮 |
| R4 | **检查失败时明确报错**，绝不显示「已是最新」 | 断言出现错误提示，且不出现「已是最新版本」 |

> **R4 是这个单元最重要的一条。** 网络断了却显示「已是最新版本」，
> 用户永远不会知道自己在用旧版——这类故障没有任何症状。

## M0 验收

**六步全走完之外，还要满足：**

| # | 标准 | 怎么验 |
|---|---|---|
| A1 | 用户打开应用看到完整轮廓，五项导航都点得开 | 人工，留截图 |
| A2 | 切换中英文，界面完全跟着变 | 人工，两张截图 |

**A3 与 A4 是 M0 真正的验收标准。**
一个会编造数据的界面、一个会把故障说成正常的更新提示，
比功能少更危险——它们会让用户在错误的信息上做决定。
