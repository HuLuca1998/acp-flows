## 为什么要重排

旧排法是**按技术切**（传输层 → 会话 → 事件流 → 权限 → 取消 → 检查点），
做出来每一块单测都绿，但**用户拿不到一件完整的事**：

- 对话页做完了，而它上面的六层（项目 / 工作 / 需求 / 计划 / 契约 / 角色）全是空的
- 结果是一个「聊天框」——没有角色、没有注入、没有契约边界

新排法**按引用关系的拓扑序**，每个里程碑是**用户能独立做成的一件事**。

## ★★ 一条硬约束：对话会话必须长期存活且只读

**2026-08-08 用户裁定**（见 [`open-questions.md`](open-questions.md) Q42）：

> 「一个对话里面，和用户沟通的 AI 只能是**同一个会话**，只有**读取权限**，
> 用于修改创建计划，不要每次用户发送消息、补充消息就启动一个新的会话。」

**我现在做错了**：`ProcessRunner.RunTurn` 每一轮都拉一个新进程、开一条新会话、
跑完就杀掉。后果——

- 用户「补充一句」时，AI **不记得上一句**（上下文每轮清零）
- 每轮重付一次启动与上下文成本
- 「一次对话」在协议上是一条会话，我做成了 N 条互不相干的

**正确的形态**：

| 谁 | 会话 | 权限 |
|---|---|---|
| 与用户沟通的（需求分析师 / 计划架构师 / 单元设计师） | **一条常驻会话**，跨轮复用 | **只读**——只产出需求、计划、契约，不碰文件 |
| 实现工程师 | 每个单元一条独立会话 | 按契约写入边界，动文件走权限请求 |
| 实现审查员 | **独立会话**（设计稿角色卡原文：「不延续规划会话」） | 只读 |

★ 「只读」怎么落实：设计稿角色表里有一列 **`会话模式 set_mode`**（值 `plan`）——
**用 ACP 的 `set_mode` 收权**，而不是靠我们自己拒绝每个请求。

这条改变了 `M4` 与 `M6` 的验收标准，见下。

## 一条重要的拆分：角色

`L0` 角色配置在依赖图里最靠前（每条消息的身份、每个 Runtime 的绑定、
**权限裁决**都来自它），但**用户不会一上来就配角色**。

所以拆成两半：

| 部分 | 排在哪 | 理由 |
|---|---|---|
| 角色**定义 + 内置默认值** | `M4` 里（第一次需要「谁在说话」时） | 不配也能跑：需求分析师=claude、实现工程师=codex… |
| 角色**可编辑**（换 Runtime / 改提示词 / 调权限裁决） | `M10` | 那是「调教」，属于熟练用户 |

★ 同时要修一个**层放错**的问题：设计稿把「权限裁决」放在**角色**上
（角色页有一列 `逐条询问 ⌄`），我做在了会话层（`session.Policy`）。
`M4` 定义角色时一并迁移。

## 每个里程碑的完成标志（用户自己做的几步）

### M2 · 把我的项目交给它

1. 点左栏「＋ 创建项目」→ **弹出对话框**，选一个本地文件夹
2. 对话框里看到「将创建 `<项目>/.acpflows/`（skills/ · memory/ · project.yaml）」
3. 对话框里看到「将追加 `.gitignore` — 忽略 `.acpflows/runs/`」
4. 对话框里看到「**发现已有 Skill 目录 · N**」，列出扫到的 `.claude/skills/` 等，
   标出哪些**校验没过**（如「缺 description」）
5. 看到 GitHub remote 与对应账号（有 remote 时）
6. 点「创建项目」→ 项目出现在左栏，**磁盘上真的多了 `.acpflows/`**
7. 提示明确：「创建项目不会开始任何工作」

**验收依据**：`INVENTORY.md` §五（弹层 1）+ §二（左栏项目区）

### M3 · 开一个工作

1. 点项目下的「＋ 新建对话」→ **弹出「新建工作」对话框**
2. 看到「已检测到 `.git` · 无未提交改动」（或如实报告有改动）
3. 选基线分支：`main` / `develop` / 「指定 commit…」
4. 看到将创建的分支名与 worktree 路径、基线 commit
5. 点「创建 worktree 并开始」→ 工作出现在项目下，**磁盘上真的多了 worktree**
6. 右栏出现「工作区」：分支、领先几个 commit、未提交改动、本次工作的 commit
7. 创建失败时工作进入 `initializing_failed`，**不退回原目录执行**

**验收依据**：`INVENTORY.md` §六（弹层 2）+ §四（右栏工作区）

### M4 · 说一句需求，它追问清楚并冻结

1. 输入一句需求 → **`Claude · 需求分析师`** 追问细节（不是直接开写）
2. 每条消息带**角色标签**与身份（头像 + 名字 + 角色）
3. 追问清楚后产出 `requirement v1`，标「**已冻结**」
4. 需求改一次 → 版本变 `v2`，旧版留着
5. 设置里看得到角色的默认绑定（需求分析师=claude 等），**这一步还不能改**
6. ★★ **连着说三句话，AI 记得前两句**——不是每句都从零开始
7. ★★ 这条会话**只读**：让它「改一下 README」，它**做不到**（`set_mode` 收了权），
   而不是「做了但被我们拦下」

**验收依据**：`INVENTORY.md` §三.2（消息流角色）+ §八（角色表）+ **Q42**

### M5 · 它给出计划，我看得懂

1. 需求冻结后 → **`Claude · 计划架构师`** 产出 `plan v1`，标「N 子计划 · M 单元」
2. 打开计划面板 → 看到**子计划 DAG**：每个子计划的状态与进度（`accepted · 3/3`）
3. 每个子计划下挂**单元**，带状态与依赖（`依赖 unit-012 · 契约未冻结`）
4. 看到**变更历史**：计划改过几版、每次为什么改
5. 重规划时**必须声明**已验收工作的处置（仍有效 / 需补充 / 需回滚 / 已废弃）

**验收依据**：`INVENTORY.md` §三.1（右上角浮标）+ 计划面板各项
**已有**：`U4.2.1` 的 `PlanVersion` 与 `Disposition`（后端模型 + 反射不可变检查）

### M6 · 它按契约干活，我看得见管得住

1. 单元开始前 → **`Claude · 单元设计师`** 产出契约 `v1`，可查看全文（YAML）
2. 契约冻结后不能改；要改就出 `v2`，旧版留着
3. 干活时每条消息显示**注入了什么**：`skill:xxx@版本 · mem-xxx`
4. AI 要动文件 → 权限卡片，**标出是否在写入边界内**（边界来自契约）
5. 点「停」→ AI 真的停，现场保留
6. 本轮结束显示「本轮小结」四行（计划变更 / 契约 / 注入清单 / 处理方式）
7. ★★ **实现工程师是另一条会话**——它写文件，而与你对话的那条始终只读
8. ★★ 一个单元跑好几轮时，实现会话**也是同一条**（记得自己刚改过什么）

**验收依据**：`INVENTORY.md` §三.2（消息流全部）+ §七（契约弹层）+ **Q42**
**已有**：对话流、权限卡片、两段式取消（`M2`/`M3` 旧编号做的）

### M7 · 它说做完了，我能验

1. 单元跑完 → 看到「验收证据 N 条 / 标准 M 条」
2. 点开证据 → **四类**：Git diff · 测试输出 · 命令记录 · 审查意见
3. 每条验收标准旁边标 `✓ ev-441` 或 `○ 无证据`
4. 证据是**应用直接采集的**，不是 AI 转述的
5. 验收通过 → 自动提交到工作分支 + 落检查点（`ck-07 · abc123`）

**验收依据**：`INVENTORY.md` §七（证据四类）+ §四（commit 列表）
**已有**：检查点与恢复（`U4.1.2`）

### M8 · 拿不准的它来问我

1. 遇到高等级决定 → 工作进入 `waiting_user`，左栏那条**亮蓝点**
2. 点开 → D2 弹层：契约全文 + 版本切换 + 验收标准与证据
3. 看到**三个选项**，每个带影响分析，其中一个标「**推荐**」
4. 选一个 → 写入 `Decision` 记录 + 生成新的契约或计划版本
5. 「稍后决定」不丢现场

**验收依据**：`INVENTORY.md` §七（D2 弹层全部）

### M9 · 它越用越懂我的项目

1. 干活中冒出经验 → 消息里出现「**记忆候选**：… · 审核」
2. 点「审核」→ 决定收不收；收了进记忆库
3. 记忆页：按项目/跨项目分组，按 `active / 候选 / 已失效` 筛选，有类型（`constraint` / `experience`）
4. Skill 页：带**版本号**、**命中计数**、**校验态**（draft 会说明为什么没过）
5. 下一轮对话的注入行里，能看到刚收的那条记忆

**验收依据**：`INVENTORY.md` §九（记忆页）+ §十（Skill 页）

### M10 · 我能调教它

1. 角色页：五个角色各自的 Runtime、`set_mode`、**权限裁决**、提示词
2. 改一个角色的 Runtime（claude ↔ codex）→ 下一轮真的换了
3. 改「权限裁决」（逐条询问 / 自动允许只读 / 一律拒绝）→ 只影响这个角色
4. 编辑角色提示词 → 下一轮生效

**验收依据**：`INVENTORY.md` §八（角色表全部）
★ 这一步要把 `session.Policy` 从会话层迁到角色层

### M11 · 我看得到它干得好不好

1. 报表页：单元一次通过率 · 平均单元耗时 · 每日已验收单元 · Runtime 使用
2. 可切「近 30 天 / 全部项目」
3. 审查驳回原因分布

**验收依据**：`INVENTORY.md` 报表页各项
