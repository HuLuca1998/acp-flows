# Duet 应用图标

`duet.svg` 是图标的**唯一真源**。`shell/src-tauri/icons/` 下的 PNG / ICNS / ICO 全部由
[`../../scripts/gen-icons.sh`](../../scripts/gen-icons.sh) 从这份 SVG 生成。

> **改图标 = 改 `duet.svg` 然后重跑脚本。**
> 直接改 PNG 的后果：下一次有人跑脚本，你的改动被静默覆盖，而且改动没有任何记录。
> 六个产物之间也会立刻不一致。**产物是构建输出，不是可编辑源文件。**

---

## 1. 三个概念方向与取舍

三个方向都从同一句产品定义出发：**两个 ACP Runtime（Claude 实现 / Codex 审查）
围绕同一个单元协作**。判据按重要性排序：① 32×32 下可辨识（Dock 小尺寸是主要露出场景）·
② 一眼读出「两个」· ③ 不与常见系统图标撞脸 · ④ 描边为主，强调色只做线与光。

| 方向 | 形态 | 为什么没选 / 为什么选 |
|---|---|---|
| **A · 契约环** | 一个环被切成两段弧（accent / neutral），两处缺口＝两个交接点 | 状态机的「循环」讲得最准，但它就是**系统加载指示器的标准形状**。32×32 下第一眼读作「正在加载」，在 Dock 里是致命误读 |
| **B · 双重环** | 两段不同半径的弧，一外一内 | 「二重」的字面翻译。但两条弧半径不同又只占对角半边，整体读作一条断掉的螺旋；32×32 下糊成一团，最先出局 |
| **C · 对位括号** ★ | 两条镜像的弧（左右各 120°，上下各留 60° 缺口）夹住中心一枚光点 | **选中**。见下 |

### 为什么选 C「对位括号」

1. **32×32 站得住。** 只有三个元素、全部沿水平中线排布，缩到 32px 后仍是三个互不粘连的
   色块（实测见 §5）。A 在 32px 下退化成一个圆环，B 退化成一团。
2. **「两个」是形状本身说的，不靠颜色。** 左右两条弧完全镜像、体量相等——
   这正是产品里两个 Runtime 的关系：**对等的执行体，不是主从**。
   即便在灰度或极小尺寸下颜色分不清，「两个」的读法也不会丢。
3. **中心那枚点是「一个单元」。** 两个 Agent 同时朝向同一个产物，
   而不是各干各的——这是 Duet 与「开两个 AI 窗口」的区别。
4. **`( )` 是代码原生符号。** 编程工具用括号做标识天然成立，
   且它不与任何系统图标（加载 / 同步 / 定位 / 录制）撞脸。
5. **对称＝规范里的语气。** 设计规范 §09 要求「工程化、精准、可核对」。
   A 和 B 都带旋转感和方向感，C 是静止的、对齐的、可测量的。

### 明确没做的事

- **没做 D 字母组合**：单字母 monogram 在 32px 下等于一个色块，且与无数应用撞形。
- **没做角色首字母 / 头像**：规范禁止给 Agent 分配新颜色，双头像会逼出第三、第四种颜色。
- **没做实心色块或渐变按钮式造型**：规范 §01「强调色只做线与光，不做大面积填充」。
  图标主体是两条 84 宽的描边弧；唯一的实心是中心 r=52 的光点，占画布面积 **0.8%**。

## 2. 用了哪些令牌

**每个颜色字面量都能在 Nocturne / Duet 令牌里找到出处，没有新造色。**
令牌真值来自 [`../_ds/nocturne/styles.css`](../_ds/nocturne/styles.css)（Nocturne 基础层）
与 [`../../docs/frontend-guide.md`](../../docs/frontend-guide.md) §1.3（Duet 产品层）。

| 用在哪 | 令牌 | 真值 | 出处 |
|---|---|---|---|
| 本体底色 · 上缘 | `--color-bg` | `#161826` | frontend-guide §1.3 |
| 本体底色 · 下缘 | `--s-canvas` | `#0e0f18` | frontend-guide §1.3 |
| 中心辉光 | `--color-accent-900` | `#2b2741` | `styles.css:39` |
| 本体描边（发丝线） | `--color-neutral-800` | `#3f424d` | `styles.css:28` |
| 左弧 —— **Claude** | `--color-accent-400` | `#b5abfc` | `styles.css:34` |
| 右弧 —— **Codex** | `--color-neutral-300` | `#cfd3e5` | `styles.css:23` |
| 中心光点（那个单元） | `--color-accent-300` | `#d2cefd` | `styles.css:33` |

角色配色照抄 frontend-guide §3.4「角色标识」：Claude = `accent-400`，Codex = `neutral-300`。
**没有给任何一方分配新颜色。**

三处用法与规范的对应：

- **底色渐变** 走的是规范 §01「四层底色由深到浅决定层级」的同一对值，
  只是从层叠关系摊平成了一个上浅下深的垂直渐变（光从上来）。
- **辉光**用 `accent-900` 从中心淡出到全透明——这是规范说的「**光**」，不是填充；
  它在 32px 下完全不可见，只在 512/1024 下给本体一点纵深。
- **发丝描边**用 `neutral-800`（规范里 neutral-800 的用途就是「描边」），
  目的是在纯黑壁纸下也能看出本体边界（实测见 §5）。

> SVG 里写的是 hex 字面量而不是 `var(--token)`。这是允许的：
> 图标是**离线光栅化的图形资产**，不经过浏览器，`var()` 在 `sips` 的渲染器里不成立。
> 但每个字面量都在 `duet.svg` 的头部注释里标了它对应哪个令牌，改色必须回令牌表取值。

## 3. 几何规格（macOS Big Sur 图标网格）

| 项 | 值 |
|---|---|
| 画布 | 1024 × 1024，四周 100px **完全透明** |
| 本体 | 824 × 824 居中，圆角 **184.33**（= 824 × 22.37%） |
| 标识外廓 | 548（= 本体的 66.5%） |
| 两条弧 | r = 232，圆心 (512, 512)，各 120°，stroke 84，`stroke-linecap="round"` |
| 上下缺口 | 各 60°（12 点与 6 点方向） |
| 中心光点 | r = 52 |

100px 透明边距不是留白习惯，是 macOS 的硬要求——Dock 用这圈空间放投影，
本体画满 1024 会被裁角。

弧宽 84 是按 32px 反推的：`84 ÷ 1024 × 32 = 2.6px`。低于 2px 的笔画在 Dock 里会消失，
这是最先定死的数字，其余尺寸都围绕它配平。

## 4. 怎么重新生成

```bash
./scripts/gen-icons.sh
```

产物写进 `shell/src-tauri/icons/`（Tauri 约定的文件名）：

| 文件 | 像素 |
|---|---|
| `32x32.png` | 32 × 32 |
| `128x128.png` | 128 × 128 |
| `128x128@2x.png` | 256 × 256 |
| `icon.png` | 1024 × 1024 |
| `icon.icns` | 含 16/32/128/256/512 及各自 @2x，共 10 张表示 |
| `icon.ico` | 含 16/24/32/48/64/128/256，共 7 张 |

前五个正是 `shell/src-tauri/tauri.conf.json` 的 `bundle.icon` 声明的那五个路径，
文件名一字不差。`icon.png` 不在 `bundle.icon` 里，它是 Tauri 官方 `tauri icon` 命令的
标准输入尺寸，也是人工核对视觉的那一张，一并留下。

脚本只用系统自带工具：`sips` 光栅化、`iconutil` 封 `.icns`、`python3`（纯标准库）
按 ICO 规范打包多尺寸 `.ico`（`sips` 写 ico 只能写单尺寸）。
非 macOS 上光栅化会退到 `rsvg-convert`，但 `.icns` 必须在 macOS 上生成。
工具缺失时脚本以退出码 2 停下并给出安装命令，不会静默产出半套东西。

**每个尺寸都是从矢量直接渲染的**，不是从 1024 缩下来的——小尺寸下前者的弧线明显更干净。

脚本最后会把每个产物的真实像素尺寸读回来核对，对不上就红（退出码 1）。
"生成了" 不等于 "生成对了"。

### 一个必踩的坑

`sips` 走严格 XML 解析器，**注释里不能出现连续两个连字符**。
在 SVG 注释里写 CSS 令牌名 `--color-accent-400` 会让整个文件解析失败。
所以 `duet.svg` 的注释里令牌名一律去掉前面那两个连字符。脚本的报错信息里也写了这条。

## 5. 32×32 下的实测结论

判据是「在 Dock 里能不能一眼认出」。用真实产物 `32x32.png`
最近邻放大 12 倍，分别衬在中灰 `#3a3a3c` / 近黑 `#0d0d0f` / 浅灰 `#d8d8da` 三种壁纸上看：

- **三个元素都没有粘连。** 左弧、光点、右弧之间保留了清晰的底色缝隙，
  「两条弧夹一个点」的结构完整成立。
- **笔画落到了整像素级的实色上。** 在 32×32 产物里直接取样：
  左弧 `#b5abfc`、右弧 `#cfd3e5`、中心点 `#d2cefd`——
  与令牌真值**逐位相等**，缩放没有把角色色洗浑。
- **角色双色仍可分辨**，但它是第二层信息；即使分不出，形状本身已经读出「两个」。
- **本体在纯黑壁纸下靠 `neutral-800` 发丝描边定住边界**，不会糊成一块黑。
- 四角 alpha 实测为 0，透明边距真实存在（`icon.png` 的 (5,5) 与 (1018,1018) 均为 `a=0`）。

16×16 下（`.icns` 里有这一档）结构仍然可读，但光点与两条弧开始接近粘连——
这是这个方案的下限，也是不再把弧加宽的原因。

## 6. 两条边界说明

1. **规范里「禁止自绘 SVG 图标」管的是界面内图标，不管这枚应用标识。**
   那条规则（frontend-guide §6.2 / 设计规范 §04）的完整语境是
   「图标只从 Phosphor regular 取」——它约束的是导航、按钮、芯片里的功能图标。
   应用标识是品牌资产，Phosphor 里不存在、也不该存在对应字形。
   **这枚图标不进 `src/constants/icon.ts`，界面里任何位置都不得引用它当功能图标。**

2. **`design/` 目录按 `design/AGENTS.md` 是只读的**（从 Claude Design 项目同步下来）。
   `design/icon/` 是新增的子目录，不在同步范围内，不会被下次 DesignSync 覆盖；
   本次是按任务明确授权的写入路径创建的。
   若后续要把这枚标识收进设计规范正文，走 `design/AGENTS.md` 写的流程：
   回 Claude Design 项目改 `Duet Spec.dc.html`，再同步下来。

### 未接进 Makefile / CI

按 `scripts/AGENTS.md` 的规则，新脚本应同步接进 `Makefile` 与 `.github/workflows/ci.yml`。
本次任务的写入边界不含这两个文件，**因此没有接**。
图标产物是提交进仓库的构建输入、不需要 CI 每次重新生成，
但「产物与 SVG 是否同步」目前**没有任何检查手段**——改了 SVG 忘了跑脚本不会被拦下。
需要补一条检查时，形式是：重新生成到临时目录后与仓库内产物逐字节比对。
