# AGENTS.md · backend/internal/app/work/reply

> 本目录的规则。**就近优先**：与 [`../AGENTS.md`](../AGENTS.md) 冲突时以本文件为准。

## 负责什么

**从 AI 的一轮回复里抠出结构化产物**：计划、单元契约、记忆候选。
以及反过来那一半——告诉 AI 该用什么格式输出（`*Instructions`）。

## 不负责什么

| 不在这里 | 去哪 | 为什么 |
|---|---|---|
| 抠出来之后存哪、发什么事件 | `app/work` | 这个包**没有副作用**，纯函数 |
| 领域规则（能不能建、状态怎么迁） | `domain/model` | 解析器不做裁决 |
| 提示词的其余部分 | `app/work/role.go` | 那是角色的事 |

## 依赖方向

| | |
|---|---|
| 允许 import | `domain/model` · 标准库 |
| 禁止 import | `app/port` · `store` · 任何有 IO 的东西 |

## 本域特有的坑

- ★★ **每一类用专属围栏**（`duet-plan` / `duet-contract` / `duet-memory`），
  不共用通用的 ```json。一轮回复里可能同时讲到计划与一条经验，
  挑错一段的后果是把配置文件当成了计划。
- ★★ **取最后一段围栏**：AI 常先贴一个示例再给真货。取第一段的话，
  用户得到的是我们自己写在提示词里的那个例子。
- ★★ **解析器与「让它这么输出」必须成对上线。** 只写解析不改提示词的话，
  那段代码永远等不到输入——单测全绿，真实路径上一条都不会出现。
  `memory_capture_test.go` 里有一条守卫断言真的传给 Agent 的 SystemPrompt。
- ★★ **记忆的 payload 里故意没有 status 字段。** AI 写不出 `active` 不是
  因为我们过滤掉了，而是因为压根没有那个入口。留一个再去过滤的话，
  总有一天有人会「顺手支持一下」。
- ★ 解析失败要**带上 AI 的原话**：静默的话，用户看到「正在规划」
  然后永远没有下文，而真正的原因躺在没人读的地方。
- ★ 包名是 `reply`，所以包内**不要用 `reply` 当变量名**——遮蔽之后
  同文件里再想调 `reply.X` 会编译失败，而错误信息指向的是一个奇怪的地方。
