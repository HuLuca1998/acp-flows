## 负责什么

项目用例：加 / 列 / 移除，以及**创建前的预演**。

## ★★ 预演与执行用同一份计划

```
PreviewInit(ctx, path) → *Preview    只读，把要做的事讲给用户听
InitializeAt(path)                   照同一个 PlanInit 算出的计划执行
```

★ `InitializeAt` **重新算一次计划**而不是把预演那份传回来：
用户看完弹层到点确认之间可能过了几分钟，期间目录变了。
拿旧计划去执行的话，「已经在了」的判断是过期的——
而那正是回滚会误删用户文件的入口。

**一致性靠的是同一个 `PlanInit`，不是同一个 Plan 实例。**

## 预演的四块，任一块坏了都不能让整次失败

| 块 | 坏了怎么办 |
|---|---|
| 初始化计划 | ★ **这一块失败才是真失败**——算不出计划就没什么可给用户看的，而让他对着空对话框点「创建」是最坏的 |
| 已有 Skill | 当作没扫到。绝大多数项目本来就没有 |
| git remote | 当作没有。本地仓库、还没推过的项目都很常见 |
| `gh` 状态 | 当作没检测。**不该因为他没装 gh 就创建不了项目** |

## 两条不能改的行为

1. **加项目默认不初始化**（`Add` 不碰盘）。静默往用户的仓库里写东西是最快失去信任的方式
2. **不擅自 `git init`**。非 git 仓库如实报告并继续——在别人的目录里建仓库是不可逆的
