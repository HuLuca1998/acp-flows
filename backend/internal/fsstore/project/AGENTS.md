## 负责什么

把一个本地目录初始化成 Duet 管得住的项目。

## ★★ 这个包的主结构就是「先说再做」

用户交出来的是**他自己的代码仓库**。所以预演不是附加功能，是主结构：

```
MakePlan(root) → *Plan     算出要做什么（只读，一个字节不写）
plan.Pending()             真正要做的那几步（跳过已经在了的）
Apply(plan)                照单执行
```

**三者用同一份 Plan。** 预演与执行各写一套的话必然漂移，
而漂移的方向永远是「预演里没说的那件事被做了」。

`Action.Reason` 是给用户看的一句话——**每一步都要说得出为什么**，
不然他凭什么点确认。有测试守着它非空。

## 四条不能改的行为

| 行为 | 为什么 |
|---|---|
| **不擅自 `git init`** | 在别人的目录里建仓库是不可逆的，而他可能有自己的打算 |
| **`.gitignore` 是追加不是覆盖** | 那是用户自己维护的文件，覆盖等于删他的规则，而他不会立刻发现 |
| 只忽略 `runs/` | `skills/` 与 `memory/` 是**他会想入 git 的东西**（项目约定、团队共享记忆），忽略掉等于替他做决定 |
| 已经在了的条目**仍然列出来** | 用户要看的是「最终会变成什么样」，不是「这次改了几个字节」 |

## 两条踩过的坑

### `MkdirAll` 对已存在目录成功返回

于是我们会把它记成「这次创建的」，回滚时 `RemoveAll` 掉——**连同里面用户已有的东西**。
计划里的 `AlreadyThere` 挡不住：它是算计划**那一刻**的快照，而执行是后来发生的。

修法：动手前再 `stat` 一次，只把真的不存在的记进回滚清单。
这个 bug 是 R5 那条测试先红发现的。

### 追加到用户文件的动作**不回滚**

撤销它要读-改-写用户自己的文件，而这中间他可能已经改过——
一次失败的初始化毁掉他手写的规则，比留下一行无害的忽略规则糟得多。

所以 R5 的判据是「**我们自己建的东西**回到原样」，不是「整个目录回到原样」。
